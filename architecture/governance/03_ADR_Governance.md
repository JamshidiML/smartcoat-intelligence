# 03 ADR Governance

Version: 1.0

Status: Draft

---

# Purpose

This document defines governance for Architecture Decision Records.

---

# ADR Philosophy

ADRs explain why architectural decisions were made.

Architecture documents explain what architecture exists.

Both are required.

---

# When To Create An ADR

Create an ADR when a decision affects:

- architecture identity
- reference models
- domain boundaries
- ontology
- canonical language
- platform architecture
- AI governance
- agent autonomy
- security model
- deployment strategy
- data governance
- knowledge governance
- decision governance

---

# ADR Statuses

- Proposed
- Accepted
- Superseded
- Deprecated
- Rejected

---

# ADR Numbering

Use:

`ADR-0001_Title.md`

Numbers are sequential and should not be reused.

---

# ADR Rule

Major architecture decisions must not be hidden inside normal documentation.

They must be recorded as ADRs.
