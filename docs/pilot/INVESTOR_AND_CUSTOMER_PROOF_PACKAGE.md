# Investor and Customer Proof Package

Status: Evidence plan; not an investment memorandum or production claim

## Proof Claim

The package should answer one question: did SmartCoat measurably improve a
governed technical-textile learning loop from requirement and prior evidence to
reviewed capture and later reuse?

It must distinguish `implemented`, `tested synthetically`, `tested with approved
sanitized pilot data`, `observed user outcome`, and `future roadmap`.

## Demonstration Narrative

1. State the narrow problem and current maturity; show the baseline reconstruction task.
2. Enter a synthetic/generalized requirement through a user-facing workflow.
3. Show retrieved reviewed lessons, evidence, source context, and why each is relevant.
4. Show missing information and let the engineer accept, correct, or reject suggestions.
5. Capture a new generalized failure; visibly separate observation from hypothesis.
6. Show field-level corrections and two human approvals; do not skip them for speed.
7. Retrieve the approved lesson in a later scenario and record whether it influenced action.
8. Present pre-registered metric results, guardrails, failures, and sample limitations.
9. Close with reusable platform capabilities, textile extension points, gaps, and next gate.

No prerecorded path should be presented as live. Demo failures remain in the
evidence log. No confidential record appears in screenshots, recordings, logs,
repository content, or investor materials.

## Customer Proof Questions

- Does the workflow fit actual R&D/Quality work without duplicate reporting?
- Are evidence, provenance, uncertainty, and approvals sufficient to trust reuse?
- Which source package and role boundary can the company lawfully approve next?
- What measurable loss, delay, or repeated work would justify expansion?
- Which integrations are truly required versus merely familiar?

## Investor Proof Questions

- Is there repeatable, measured user value beyond a chatbot or document search?
- Which primitives are horizontal: tenant isolation, provenance, review, lifecycle,
  retrieval, metrics, audit, and governed assistance?
- Which assets are industry-specific: language, schema mappings, methods, rules,
  evidence conventions, and expert validation?
- What is the cost and time to configure a second company without mixing data?
- Which critical product, security, governance, and go-to-market risks remain?

## Scale Decision Package

Recommend only one next step: stop, iterate the same workflow, repeat at a second
site, or add one use case. Include cost-to-configure, support load, user adoption,
guardrails, unresolved defects, data readiness, technical gaps, and professional
reviews. Cross-company analytics or model training is not an automatic scale path;
it requires an independent product, governance, security, and legal decision.
